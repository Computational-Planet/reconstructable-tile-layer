# 工程性能优化后的完整技术路径

## 1. 优化前技术路线基线

当前古地理重建流程保持为客户端渲染框架内完成：

1. 从静态 JSON 加载现今板块多边形数据，并按 `PlateID` 和 `FeatureID` 分类。
2. 读取 `.rot` 板块旋转文件，构建 `RotationOperator`，用于按地质年龄计算板块旋转矩阵。
3. 每个多边形建立 `QuadTreeTileProcesser`，按目标层级或根层级查找需要显示的瓦片。
4. 对每个瓦片请求影像 provider 的原始瓦片图片。
5. 使用 `tile-processer-webgl` 包内部的不可见 WebGL canvas 池执行瓦片重投影；当瓦片与多边形边界相交时，使用裁剪 shader 输出透明边界结果。
6. 将重投影结果转为 data URL，并作为 Cesium `Primitive` 的影像材质显示。
7. 当 age 变化时，通过板块旋转矩阵更新每个 primitive 的 `modelMatrix` 和可见性。

本轮优化不改变上述路线，不替换四叉树裁剪、WebGL 重投影、Cesium Primitive 贴图和板块旋转这些核心方法。

## 2. 优化目标与约束

优化目标集中在工程执行效率和稳定性：

- 减少重复请求、重复重投影和重复 primitive。
- 让瓦片生成过程可等待、可取消、可被后续操作覆盖。
- 在不破坏单个 WebGL renderer 状态的前提下，通过内部 canvas 池提高瓦片绘制阶段的并发度。
- provider 切换和清空时同步释放引用，避免旧 primitive 和旧缓存继续占用内存。
- 高频 age 更新时只应用最后一次结果，避免旧异步结果覆盖新状态。

约束如下：

- 不引入 WebGPU、服务端预处理、Web Worker 或新的空间索引。
- 不改变公开调用接口：`generateTilePrimitivesOnLevelN`、`generateTilePrimitivesAtRoot`、`updateAge`、`updateProvider` 继续保留。
- 当前只优化 `SimpleGeoReconstructManager` 这条新古地理重建路径，旧的 `TilePrimitivesManager` 测试路径不做同等重构。

## 3. 优化后的完整执行流程

### 初始化

`SimpleGeoReconstructManager.init()` 现在按顺序完成：

1. 清空已有板块、瓦片列表缓存和旋转矩阵缓存。
2. 加载并展开古地理多边形 JSON。
3. 按板块和要素构建 `QuadTreeTileProcesser`。
4. 等待 `RotationOperator.init()` 完成后再将 manager 标记为 ready。

这样可以避免旋转文件尚未初始化完成时就进入 age 更新或瓦片生成。

### Level N / Root 瓦片生成

`generateTilePrimitivesOnLevelN(viewer, level)` 和 `generateTilePrimitivesAtRoot(viewer)` 统一走同一条任务流：

1. 从每个多边形的四叉树中收集 `NodeInfo`。
2. 根据 `featureId + x/y/l` 生成 `tileId`。
3. 跳过已经存在 primitive 的 tile，也跳过正在生成中的 tile。
4. 将待生成项封装为 `TileTask`。
5. 使用并发上限 8 的任务队列请求和处理影像。
6. WebGL 绘制阶段由 `CesiumTileProcesser` 的内部不可见 canvas 池调度；单个 renderer 内串行，pool 层可并行处理多个瓦片。
7. 成功生成的 primitive 按每帧 32 个批量加入 Cesium scene。
8. 每个批次和最终完成后调用 `viewer.scene.requestRender()`。

每次生成会创建新的 generation token。如果 provider 切换、清空或另一次生成发生，旧任务的结果会被丢弃，不再写入 scene。

## 4. 缓存与去重策略

### 原始影像缓存

位置：`CesiumTileProcesser`

key 组成：

```text
providerId:x/y/level
```

用途：

- 同一 provider、同一瓦片只请求一次原始影像。
- 同一瓦片的并发请求共用同一个 Promise。
- 请求失败时移除 Promise，允许后续重试。

### 重投影结果缓存

位置：`CesiumTileProcesser`

完整瓦片 key：

```text
providerId:x/y/level:full
```

裁剪瓦片 key：

```text
providerId:x/y/level:clip-polygonHash
```

用途：

- 同一 provider、同一瓦片、同一裁剪边界不重复执行 WebGL 绘制和 `toDataURL()`。
- 同一结果在生成中的并发请求共用同一个 Promise，避免同一 tile 被分配到多个 renderer。
- 不同 provider 拥有不同 `providerId`，避免切换底图后串用旧图。

### 瓦片列表缓存

位置：`SimpleGeoReconstructManager`

key 组成：

```text
featureId:tilingScheme:mode:level
```

用途：

- 同一投影类型下重复加载同一层级时，不重复递归查询四叉树。
- provider 投影类型变化时清空，因为瓦片切分方式可能变化。

### 旋转矩阵缓存

位置：`SimpleGeoReconstructManager`

key 组成：

```text
plateId:age
```

用途：

- 同一 age 下不同 primitive 共用同一板块矩阵。
- 重复拖动到同一 age 时不重复计算旋转矩阵。

## 5. 并行化与调度策略

并行边界如下：

- 影像请求可以并行，默认并发数为 8。
- 瓦片任务准备可以并行，默认并发数为 8。
- `CesiumTileProcesser` 默认创建内部不可见 canvas 池；demo 当前配置 `poolSize: 4`。
- 单个 renderer 的绘制、裁剪、`toDataURL()` 必须串行，但多个 renderer 可以并行处理不同 tile。
- Cesium primitive 添加按批次执行，每帧最多 32 个，降低一次性加入大量 primitive 造成的主线程卡顿。

这种调度方式保留了原来的 WebGL 重投影实现，把 I/O、任务准备和多 canvas 绘制都纳入调度，同时保护每个 renderer 的状态一致性。调用方不再需要手动挂载处理用 canvas。

## 6. Provider 切换与资源清理

`updateProvider(viewer, provider)` 现在先判断新旧 provider 的 tiling scheme 类型：

- 如果投影类型不变：保留已有四叉树和 primitive 几何，只清空影像/重投影缓存，并重新生成当前 primitive 的影像材质。
- 如果投影类型变化：调用现有 `quadTree.updateProvider(provider)` 重建四叉树，清空瓦片列表缓存，移除所有旧 primitive，等待用户重新加载瓦片。

`clearAllTiles(viewer)` 会：

1. 增加 generation token，使旧瓦片任务失效。
2. 清空正在生成的 tile 标记。
3. 清空 WebGL 处理器缓存。
4. 从 Cesium scene 移除所有 primitive。
5. 同步清空每个多边形下保存的 primitive 记录。

`CesiumTileProcesser` 在每次 WebGL 绘制完成后会释放本次创建的 texture 和 textureCoord buffer；`destroy()` 会释放内部 renderer 的 WebGL 资源和不可见 canvas 引用，降低长时间重复加载时的 GPU 资源压力。

## 7. Age 更新与渲染刷新策略

`updateAge(age)` 使用 latest-wins 策略：

1. 每次调用增加 age update token。
2. 并行计算所有板块的矩阵，矩阵结果进入 `plateId:age` 缓存。
3. 如果计算完成时 token 已经过期，直接丢弃旧结果。
4. 只有最新一次 age 更新会写入 primitive 的 `modelMatrix` 和 `show`。
5. 面板层保留原有 `.then(() => viewer.scene.requestRender())` 的统一刷新方式。

可见性仍沿用原逻辑：

```text
age <= ValidTime.Begin && age >= ValidTime.End
```

## 8. 性能验证方案

已执行构建验证：

```bash
pnpm --filter tile-processer-webgl build
pnpm --filter tile-processer-demo build
```

建议继续手动验证以下场景：

- Level N 加载：确认能正常显示目标层级瓦片。
- Root 加载：确认根层级瓦片仍按四叉树结果显示。
- 重复点击加载按钮：确认不会产生重复 primitive。
- 同一 provider 重复加载：确认已有 primitive 会跳过，已缓存影像不会重复请求。
- provider 切换：同投影 provider 应刷新材质，不重建四叉树；不同投影 provider 应清空旧 primitive 并等待重新加载。
- 快速拖动 age：最终显示状态应与最后一次 age 输入一致。
- 长时间加载、清空、切换 provider：primitive 记录和 WebGL 临时资源不应持续增长。

## 9. 不纳入本轮优化的内容

本轮不包含以下方向：

- 不引入 WebGPU。
- 不引入服务端预处理或预切片。
- 不引入 Web Worker。
- 不替换现有四叉树裁剪算法。
- 不替换现有 WebGL shader 重投影/裁剪路线。
- 不改造旧的 `TilePrimitivesManager` 测试路径。
- 不调整地质模型、旋转模型或数据文件格式。
